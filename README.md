# DIP: Decision Integrity Protocol

DIP is an open protocol and reference implementation for one question: **was this action authorized, and can anyone check that it was?**

- Authority is declared explicitly, signed, and versioned.
- Every request is authorized as **ALLOW or DENY** by deterministic rules, never by an AI or a probabilistic model.
- Approvals are a separate workflow. An approval never grants authority on its own.
- An action can run only through an execution boundary, and only for a verified ALLOW decision for that exact request.
- Every attempt is recorded in a signed, hash-chained ledger that an independent verifier can check without trusting the service that wrote it.

```
DECLARED → AUTHORIZED → EXECUTED → PROVEN
```

AI systems may propose actions. The business declares what is allowed. DIP decides, controls execution, and produces proof.

## Status

**Reference implementation. Not ready for production use.**

- The protocol, SDK, REST API, CLI, verifier, conformance fixtures, storage and deployment files are implemented and tested in this repository (see [docs/BUILD_STATUS.md](docs/BUILD_STATUS.md)).
- Connectors use placeholder endpoints. No live payment or ERP integration has been verified.
- The conformance fixtures were generated by this project. No independent implementation has run them yet.
- No external security review has been performed. See [docs/RELEASE-AUDIT.md](docs/RELEASE-AUDIT.md) for the open gaps.

## Quick start

Requires Node.js 22 and pnpm 10.

```bash
git clone https://github.com/pavancharak/dip.git
cd dip
pnpm install --frozen-lockfile
pnpm -r run build
node examples/run.mjs              # four end-to-end scenarios, 4/4 should pass
node examples/sdk-quickstart.mjs   # minimal SDK walkthrough
node apps/cli/dist/bin.js conformance run conformance   # 16/16 should pass
```

For a step-by-step guide, see [docs/QUICKSTART.md](docs/QUICKSTART.md).

## What is in the repository

| Path                                   | What it is                                                             |
| -------------------------------------- | ---------------------------------------------------------------------- |
| `packages/crypto`                      | Canonical JSON, SHA-256, domain-separated Ed25519                      |
| `packages/authority`                   | Authority declarations, trust roots, signed publication and revocation |
| `packages/authorization`               | Request normalization and the two-outcome engine                       |
| `packages/approval`                    | Approval workflow, separate from authorization                         |
| `packages/execution`                   | Protected execution boundary                                           |
| `packages/evidence`, `packages/ledger` | Signed evidence envelope and hash-chained ledger                       |
| `packages/verifier`                    | Independent verifier; depends only on `@dip/crypto`                    |
| `packages/connectors`                  | Connector contract and adapters                                        |
| `packages/sdk`                         | Developer client                                                       |
| `packages/storage`                     | PostgreSQL storage (event log, stores, PGlite and node-postgres)       |
| `packages/conformance`                 | Reference runner for the conformance fixtures                          |
| `apps/api`                             | REST API and server                                                    |
| `apps/cli`                             | The `dip` command                                                      |
| `conformance/`                         | Language-neutral JSON conformance fixtures                             |
| `examples/`                            | Runnable examples                                                      |
| `docs/`                                | Specification, guides, deployment, threat model                        |

## Security

Please do not report vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

## Independence

DIP is a standalone protocol. It does not depend on any other project to operate or to verify its evidence, and its verifier needs only the public trust roots and the bundle.
